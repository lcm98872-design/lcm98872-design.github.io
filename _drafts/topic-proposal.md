## 한 줄로 말하면

**공강시간과 지금 있는 건물, 하고 싶은 활동을 넣으면, 오가는 시간을 빼고도 시간이 충분한 캠퍼스 안 장소를 추천해 주는 웹서비스**를 만든다.

## 누가 쓰는가

### 페르소나

| 항목 | 내용 |
|---|---|
| 이름 | [김OO] / [2]학년 / [시스템경영공학부] |
| 상황 | [화요일 10:30 수업이 끝나고 12:10 수업까지 1시간 40분이 빈다] |
| 목표 | 이 시간에 [과제를 하거나 쉬고], 다음 수업에 늦지 않게 돌아오고 싶다 |
| 불편 | [도서관은 다음 강의실과 멀어서 오가면 30분이 날아간다. 가까운 곳은 어디가 비어 있는지, 콘센트가 있는지 몰라서 결국 과방이나 벤치에서 폰만 본다] |
| 제약 | 노트북을 들고 다닌다. 고르는 데 5분 이상 쓰고 싶지 않다 |

### 사용자 스토리

> 공강이 애매하게 남은 학생으로서, 다음 수업에 늦지 않으면서 할 일을 할 수 있는 장소를 바로 알고 싶다.
> 왜냐하면 매번 어디 갈지 고민하다가 시간을 흘려보내기 때문이다.

## 어떤 불편인가

[친구 N명에게 "공강 때 주로 어디 가?", "뭐가 불편해?"를 물어본 결과를 적는다.]

- [예: 3명 중 2명이 "애매하게 1시간 남으면 그냥 과방에 있다"고 답했다]
- [예: "콘센트 있는 자리를 찾다가 시간이 다 간다"]
- [예: "도서관 가고 싶은데 왕복 생각하면 안 가게 된다"]

지금은 다들 **기억이나 감으로** 정하고 있다. 캠퍼스 지도는 건물 위치만 알려 주고, 그 장소에서 무엇을 할 수 있는지, 몇 시까지 여는지, 다녀오면 실제로 몇 분이 남는지는 알려 주지 않는다.

## 무엇을 만드는가

| 단계 | 내용 |
|---|---|
| 입력 | 공강 시작·끝 시각, 지금 있는 건물, 다음 수업 건물, 하고 싶은 활동(공부 / 휴식 / 식사 / 노트북 작업) |
| 계산 | 건물 사이 걷는 시간으로 **이동 시간을 빼고 실제로 머물 수 있는 시간**을 구한다 |
| 걸러내기 | 활동이 맞지 않거나, 그 시간에 문을 닫았거나, 머무는 시간이 최소 기준보다 짧은 장소는 뺀다 |
| 출력 | 남는 시간이 긴 순서로 장소 목록과 **추천 이유**를 보여 준다 |

예를 들어 공강이 100분이고, 지금 건물에서 도서관까지 8분, 도서관에서 다음 수업 건물까지 12분이면 실제로 도서관에 있을 수 있는 시간은 **80분**이다. 이 계산을 장소마다 해서 비교해 주는 것이 이 서비스의 핵심이다.

## 이번 학기에 어디까지 할 것인가

### Scope (이번 버전)

| 우선순위 | 기능 |
|---|---|
| Must | 장소 등록: 이름, 건물, 운영시간, 할 수 있는 활동, 콘센트 여부 |
| Must | 건물 사이 걷는 시간 등록 |
| Must | 공강 조건을 입력하면 추천 장소 목록과 머물 수 있는 시간 표시 |
| Should | 추천에서 빠진 장소와 빠진 이유 표시 (예: "13:00에 문 닫음") |
| Could | 장소별 한 줄 후기 |

- 대상 범위: **부경대 [대연캠퍼스] 안의 장소 [15]곳 정도**. 데이터는 내가 직접 돌아다니며 조사해 넣는다.
- 추천 결과는 3초 안에 나와야 한다. 입력은 한 화면, 4칸 이내로 끝나야 한다.

### Out of Scope (이번 버전에서 하지 않는 것)

- **실시간 혼잡도**: 누가 계속 갱신할지 해결책이 없다.
- **지도 API 길찾기**: 걷는 시간은 직접 잰 값으로 대신한다.
- **로그인과 개인 시간표 저장**: 한 번 입력하고 결과를 보는 것까지만 한다.
- **캠퍼스 밖 카페·식당**: 범위가 너무 넓어진다.
- **모바일 앱**: 웹으로만 만든다.

## 주제를 정하면서 AI에게 시킨 것

AI(ChatGPT, Claude)에게 처음에는 "대학생이 불편해하는 걸로 주제 10개"를 시켰다. 그런데 몇 번을 다시 시켜도 맞지 않았다.

1. **처음 받은 주제**는 과제 마감 모음판, 물품 대여 장부 같은 기록·조회 서비스였다. 캘린더나 노션으로 충분히 되는 것들이라 버렸다.
2. **"복잡했으면 좋겠다"고 하자** 근무 배정 최적화, 상자 포장 조합처럼 알고리즘이 들어간 주제를 냈다. 복잡하긴 한데 쓸 사람이 떠오르지 않았다.
3. **생활 쪽으로 넓혀 달라고 하자** 짐 보관 최적화, 급여 오류 분석기 같은 주제가 나왔다. 문제는 있을 수 있지만 그걸 해결하려고 웹사이트를 찾아 들어갈 사람은 없을 것 같았다.

여기서 깨달은 건 AI는 **"불편이 있다"와 "그걸 위해 이 서비스를 쓴다"를 구분하지 못한다**는 점이었다. 결국 주제는 AI 목록에서 고르지 않고, 내가 평소에 공강 때마다 고민하던 걸로 정했다. AI에게는 그걸 한 문단 소개문으로 정리하는 것만 시켰다.
